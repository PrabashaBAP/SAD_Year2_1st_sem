What is System Design?

  • Process of defining HOW a system will operate
  • Covers: user interaction, data I/O, components
  • Covers: technical architecture, controls, security
  • Analysis asks WHAT — Design asks HOW
  • Transforms requirements into technical specs
🎯

Design Converts Requirements Into

  • Screens / Forms — data entry interfaces
  • Reports — formatted outputs for stakeholders
  • Workflows — step-by-step process logic
  • Database Structures — tables, fields, relationships
  • System Components / Services — modules, functions
  • Interfaces Between Modules — communication links
  • Security and Control Mechanisms
✅

A Well-Designed System Is

  • Usable — easy to learn and use
  • Efficient — tasks completed quickly, less effort
  • Secure — protects data and operations
  • Aligned with Business Needs
  • Reliable — consistent and predictable
  • Maintainable — easy to update and modify
⌨️

Input Design

  • Specifies how data enters the system
  • Ensures: accurate, complete, consistent, timely, secure
  • Sources: users, scanners/sensors, APIs, files, batch
  • Controls: validation, range checks, format checks
  • Good error messages explain HOW to fix errors
  • Never erase all data when one field is wrong
📊

Output Design

  • Specifies how information is presented
  • Helps: make decisions, monitor operations
  • Types: External, Internal, Detailed, Summary
  • Types: Real-Time, On-Demand, Scheduled
  • Principles: Relevance, Readability, Usability
  • Principles: Timeliness, Accuracy, Security
🖥️

UI Design Principles

  • Consistency — uniform look and behavior
  • Feedback — system responds to user actions
  • Navigation — easy to move through the system
  • Error Prevention — stop mistakes before they happen
  • Accessibility — usable by all users
  • UI (visual) ≠ UX (overall experience)
🔒

CIA Security Triad

  • Confidentiality — only authorized access
  • Integrity — data accurate, unaltered
  • Availability — system accessible when needed
  • Security must be designed in from the start
  • Adding security later is expensive
  • Authentication, authorization, encryption, logging
🏛️

Architecture Design

  • Defines overall technical structure of the system
  • Hardware/software arrangement
  • Layers and components
  • Data storage design
  • Communication between components
  • Deployment environment
  • Answers: How will parts work together?
Core Theory

Purpose of System Design

A well-designed system must satisfy four key properties. These are all exam-testable!

👤

1. Usable

  • Easy for users to learn and use
  • Screens, forms, buttons clearly understood
  • Tasks completed with minimum confusion
  • Simple instructions, messages, and navigation
  • Why: difficulty → mistakes, avoidance, extra training
⚡

2. Efficient

  • Users complete tasks quickly with less effort
  • Reduce unnecessary steps
  • Minimize repeated data entry
  • Provide fast response times
  • Automate routine tasks where possible
  • Why: efficiency improves productivity, saves time
🔒

3. Secure

  • Protect data from unauthorized access/attacks
  • Authentication (login control)
  • Authorization (role-based access)
  • Data validation, encryption
  • Logging and monitoring
  • Why: sensitive data, legal risks, trust
🏢

4. Aligned with Business Needs

  • Supports actual goals and priorities
  • Matches business workflows
  • Supports decision-making
  • Meets reporting requirements
  • Follows policies and regulations
  • Why: technically good ≠ business success

Design Area 1

Input Design

Everything about how data enters the system — one of the most testable topics!

📋

What is Input Design?

  • Process of specifying how data enters the system
  • Ensures data is accurate, complete, consistent
  • Ensures data is timely and secure
  • Inputs from: users, scanners, sensors
  • Inputs from: external APIs, uploaded files, batch imports
🎯

Objectives of Input Design

  • Minimize data entry errors
  • Ensure only valid data enters the system
  • Reduce data entry effort and time
  • Protect data integrity from source to storage
  • Guide users through the data entry process
  • Provide clear, helpful error feedback
✅

Input Validation Techniques

  • Format check — data in correct format (date: DD/MM/YYYY)
  • Range check — value within acceptable limits (age: 0–120)
  • Completeness check — required fields are filled
  • Consistency check — related fields match logically
  • Existence check — verifies against database records
  • Reasonableness check — value makes logical sense
⚠️

Input Controls and Error Handling

  • Provide inline validation messages (real-time)
  • Highlight the problematic field clearly
  • Explain HOW to fix the error specifically
  • Never erase all entered data when one field is wrong
  • ❌ Bad: "Invalid input."
  • ✅ Good: "NIC must contain 12 digits."
💡

Input Design Best Practices

  • Use drop-downs to constrain choices
  • Default values for common inputs
  • Tab order follows logical reading sequence
  • Group related fields together
  • Mandatory fields clearly marked (e.g., *)
  • Provide helpful placeholder text
🔢

Types of Input Controls

  • Text fields — free text input
  • Drop-down lists — constrained selection
  • Radio buttons — single choice from options
  • Checkboxes — multiple selections
  • Date pickers — structured date input
  • File upload — importing external data
Design Area 2

Output Design

How information is presented — types, principles, and common mistakes.

📤

External Outputs

  • Sent OUTSIDE the organization
  • Customer invoice
  • SMS / email notification
  • Payment receipt
  • Legal documents sent to regulators
📥

Internal Outputs

  • Used INSIDE the organization
  • Management dashboard
  • Inventory status report
  • Staff performance report
  • Financial summary for management
📋

Detailed Reports

  • Transaction-level information
  • Every individual record shown
  • Example: Daily sales transaction list
  • Used by operational staff
  • High volume of data
📈

Summary Reports

  • Aggregated data for decision-making
  • Totals, averages, trends
  • Example: Monthly sales by region
  • Used by managers and executives
  • Less detail, more insight
⚡

Real-Time Outputs

  • Immediate feedback to the user
  • Example: "Registration successful"
  • Example: Live inventory levels
  • Example: Real-time stock price
  • Critical for transactional systems
🕐

On-Demand vs Scheduled

  • On-Demand: generated when user requests
  • On-Demand example: search result, custom report
  • Scheduled: generated at fixed times
  • Scheduled example: weekly attendance summary
  • Scheduled: automatically sent, no user trigger

Key Output Design Principles (A–F)

PrincipleWhat It MeansExample
A. RelevanceOnly show what the user needs for the taskManager sees summary, not every transaction
B. ReadabilityClear headings, labels, spacing, consistent formattingAligned columns, proper number formatting
C. UsabilityOutputs support user actionReport has filters, sort, export options
D. TimelinessInformation reaches user when neededDaily reports available at start of business
E. Accuracy & ReliabilityOutputs reflect correct processed dataSales totals match transaction records exactly
F. Security & PrivacySensitive outputs restricted to authorized usersSalary report only visible to HR department
❌

Common Output Design Mistakes

  • Too much detail for managers (overload)
  • Missing important filters and context
  • Unclear labels and abbreviations
  • Inconsistent date/number formats
  • Exposing sensitive data to wrong users
  • Reports not aligned with decision needs
Design Area 3

User Interface Design

UI vs UX, the 5 core principles, and how they apply to real system screens.

🖥️

What is UI Design?

  • Defines how users interact with the system
  • Includes: screens, menus, controls, navigation
  • Includes: messages, visual layout
  • UI = visual and interaction elements
  • UX = overall experience of using the system
  • Good UI + poor UX = attractive but hard to use
🔄

Consistency

  • Same look and behavior throughout the system
  • Same button styles, colors, labels everywhere
  • Users learn once, apply everywhere
  • Example: Save button always green, top-right
  • Inconsistency causes confusion and errors
💬

Feedback

  • System must respond to every user action
  • Show confirmation: "Record saved successfully"
  • Show progress: loading indicators
  • Show errors: what went wrong and how to fix it
  • Silence after an action creates uncertainty
🧭

Navigation

  • Users must always know where they are
  • Clear menu structure and breadcrumbs
  • Easy to move between sections
  • Back button / cancel always available
  • Logical flow from one step to the next
🛡️

Error Prevention

  • Design to prevent errors before they happen
  • Use constraints: drop-downs, date pickers
  • Confirm destructive actions: "Are you sure?"
  • Disable buttons when action is not possible
  • Better to prevent than to display error messages
♿

Accessibility

  • System usable by all users, including those with disabilities
  • Screen reader compatibility
  • Sufficient color contrast
  • Keyboard navigation (no mouse required)
  • Text alternatives for images
  • Font size adjustable
⚖️

UI vs UX — The Key Difference

  • UI (User Interface): the visual/interaction elements — buttons, forms, colors, layout
  • UX (User Experience): the overall feeling of using the system — ease, satisfaction, flow
  • A system can look attractive (good UI) but still be difficult to use (poor UX)
  • Good design requires BOTH good UI and good UX
  • UX includes the full journey from start to goal completion
Design Area 5

Security Considerations

The CIA Triad is one of the most testable topics in this chapter — learn all three!

⚠️

Why Security Must Be Designed In from the Start

  • Security should NOT be added only at the end — it must be integrated from the beginning
  • If ignored early: vulnerabilities become deeply embedded in the system
  • Fixing security issues later is extremely expensive
  • User trust is damaged if a breach occurs
  • Legal and compliance risks increase without proper security

The CIA Triad — Core Security Objectives

🔐

Confidentiality

Only authorized users can access information. Data is protected from unauthorized viewing or disclosure.

Example: Student marks visible only to authorized staff and the student themselves.
🛡️

Integrity

Data remains accurate and unaltered except by authorized actions. Protects against unauthorized modification.

Example: Exam results cannot be changed without proper authorization and audit trail.
✅

Availability

Systems and data must be available when authorized users need them. Protects against downtime and denial of service.

Example: LMS should be accessible during registration periods and exam times.

Security Mechanisms in System Design

🔑

Authentication

  • Verifies WHO the user is
  • Username and password login
  • Multi-factor authentication (MFA)
  • Biometric verification
  • Session tokens and cookies
🎫

Authorization

  • Controls WHAT the user can do
  • Role-based access control (RBAC)
  • Admin vs user vs guest roles
  • Permissions on specific data/functions
  • Least privilege principle
🔐

Encryption & Other Controls

  • Encryption: scrambles data to prevent reading
  • Data validation: prevents bad data from entering
  • Logging and monitoring: tracks all actions
  • Audit trails: record of who did what, when
  • Input sanitization: prevents injection attacks
