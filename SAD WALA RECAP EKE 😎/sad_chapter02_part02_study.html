1. Waterfall Model

Linear Sequential
Features

Waterfall Model

  • A linear model — phases flow downwards like water
  • Cannot return to previous phases once completed
  • Each phase has clear outputs which become input for the next
  • Works best when everything is known at the start (requirements, timeline, budget)
🔑 Key rule: No going back. All requirements must be defined upfront.
Suitability & Profile

When to Use Waterfall

  • Requirement stability: Very High needed
  • Customer involvement: Low
  • Flexibility: Very Low
  • Speed: Slow
  • Documentation: Very High
  • Risk handling: Poor
✅ Best for: Small, stable projects with fixed requirements

2. Spiral Model

Risk-Driven Iterative
Features

Spiral Model

  • Project moves in repeated loops called spirals
  • Each loop focuses on studying and removing risks
  • Early versions (prototypes) built quickly for customer review
  • Every cycle adds more detail and clarity to the solution
🔑 Unique feature: Risk analysis is performed at every loop.
Profile

Spiral at a Glance

  • Requirement stability: Low needed (handles change)
  • Customer involvement: Very High
  • Flexibility: Very High
  • Speed: Slow (thorough risk analysis)
  • Cost: High
  • Risk handling: Excellent
  • Early prototyping: Yes
✅ Best for: High-risk, large, complex systems

3. V-Model

Verification & Validation
Features

V-Model

  • Development phases on left side; testing phases on right side
  • For every development activity, there is a matching testing activity
  • Ensures quality is built in from the beginning
  • Very systematic, structured approach
🔑 Key shape: Like the letter V — development goes down the left, testing goes up the right, meeting at coding in the centre.
Usage & Profile

V-Model Usage

  • Ideal when requirements are complete and detailed
  • Used where quality cannot be compromised: health, military, manufacturing
  • Flexibility: Low
  • Documentation: Very High
  • Risk handling: Good
✅ Best for: Safety-critical systems — medical devices, flight navigation, driverless cars
✅ Advantages

V-Model Advantages

  • Strong verification and validation at each stage
  • Bugs are found early because testing starts early (planning)
  • Works well for large, critical systems where reliability is key
  • Clear structure — every phase has a paired test
❌ Limitations

V-Model Limitations

  • Almost no flexibility for changes mid-project
  • Lots of documentation required
  • Testing team must be equally skilled to match development phases
  • Not suitable for projects with unclear or changing requirements
⚠️ Suitable projects: heart monitoring systems, driverless car sensors, flight navigation — failures are life-threatening.

4. Unified Process (UP)

OO + Architecture-Focused
Features

Unified Process (UP)

  • Uses object-oriented concepts and UML diagrams
  • Development broken into four main phases: Inception, Elaboration, Construction, Transition
  • Each phase contains iterations that refine the system
  • Architecture-focused model — ensures strong system foundation
🔑 The 4 UP Phases: Inception → Elaboration → Construction → Transition
Profile

UP at a Glance

  • Requirement stability: Medium
  • Customer involvement: Medium
  • Flexibility: High
  • Speed: Medium
  • Cost: High
  • Risk handling: Medium
  • Documentation: High
  • Early prototyping: Partial
✅ Best for: OO complex systems, enterprise applications

5. Iterative Model

Evolve Through Feedback
Features

Iterative Model

  • Create a simple and working version first
  • Improve it step by step in multiple iterations
  • Focuses on feedback after each version
  • Good when starting with unclear or changing requirements
🔑 Think of it as: build → get feedback → improve → repeat.
Profile

Iterative at a Glance

  • Requirement stability: Low–Medium (handles change)
  • Customer involvement: High
  • Flexibility: High
  • Speed: Fast
  • Cost: Medium
  • Early prototyping: Yes
  • User feedback: High
✅ Best for: Evolving requirements, unclear scope projects

6. Incremental Model

Module-by-Module Delivery
Features

Incremental Model

  • System divided into smaller modules
  • Each increment delivers part of the functionality
  • Early increments help customers see working features quickly
  • Combines Waterfall phases with step-by-step delivery
🔑 Key difference from Iterative: Incremental adds new features each time; Iterative refines the same features.
Profile

Incremental at a Glance

  • Requirement stability: Medium
  • Customer involvement: High
  • Flexibility: High
  • Speed: Fast
  • Cost: Medium
  • Early prototyping: Yes
✅ Best for: Fast modular apps, large systems delivered in phases

7. RAD Model

Rapid Application Development
Features

RAD Model

  • Focus on speed and quick delivery
  • Uses prototypes instead of full documentation
  • User feedback collected in every cycle
  • Components developed in parallel
  • Uses reusable software components
  • Works well with small, skilled teams
Usage Conditions

When RAD Works

  • Project needs to be delivered fast
  • Requirements will evolve based on user feedback
  • Users are available to work closely with developers
  • Application can be divided into modules
✅ Best for: Mobile apps, UI-heavy web apps, CRM systems, startup prototypes
✅ RAD Advantages

Why Choose RAD

  • Very fast development cycles
  • Users get to see working versions early
  • Reduces overall project risk through early feedback
  • High customer satisfaction
  • Easy to make changes based on user feedback
❌ RAD Limitations

RAD Drawbacks

  • Requires skilled developers and designers
  • Needs active, continuous user involvement
  • Not suitable for large or complex systems
  • Integration of many prototypes can become difficult
  • Customer involvement: Very High (burden on business)
