What is a System?

Topic 1
Definition

System

A collection of interrelated components working together toward a common purpose by accepting inputs, processing them, and producing outputs.

💡 Key formula: Input → Process → Output
8 Characteristics

Characteristics of a System

  • Components – Subsystems/elements
  • Boundary – Scope/limits of the system
  • Environment – Everything outside boundary
  • Interface – Points of interaction
  • Input – Data/materials entering
  • Output – Final product/information
  • Feedback – Mechanism for adjustment
  • Control – Ensures intended function

Types of Systems

Topic 2
Open vs Closed

Open System

Interacts with and is influenced by its environment. Example: a business organization receiving market feedback.

Open vs Closed

Closed System

Does not interact with its environment; self-contained. Example: a chemical reaction in a sealed container.

Classification

Physical vs Abstract

Physical: Tangible entities (computers, machines).
Abstract: Conceptual/logical (software, algorithms).

Classification

Natural vs Man-made

Natural: Ecosystems, solar system.
Man-made: Banking system, payroll system.

Classification

Deterministic vs Probabilistic

Deterministic: Output is predictable (calculator).
Probabilistic: Uncertain outcomes (weather forecasting).

Classification

Formal vs Informal

Formal: Documented and structured procedures.
Informal: Undocumented, ad-hoc communication channels.

System Analysis & Design (SAD)

Topic 3
Definition

What is SAD?

A structured process that involves understanding how an existing system functions and designing a new or improved system to meet organizational goals.

Objectives

SAD Objectives

  • Improve business efficiency and effectiveness
  • Identify and solve problems systematically
  • Ensure IS meets user requirements
  • Design systems that are flexible, reliable, cost-effective
Importance

Why SAD Matters

  • Reduces project failure risk
  • Improves communication between users and developers
  • Provides documentation and structure
  • Aligns IT solutions with business goals
Components

Components of SAD

  • System Analysis – Study and understand current system
  • System Design – Blueprint for the new system
  • Feasibility Study – Evaluate if system is viable
  • Requirements Gathering – Collect user needs

SDLC — System Development Life Cycle

Topic 4
Definition

What is SDLC?

A framework that defines the stages involved in developing an information system. Provides a structured approach to planning, creating, testing, and deploying systems.

Phases

SDLC Phases

  1. Planning / Initiation
  2. System Investigation / Feasibility
  3. Requirements Analysis
  4. System Design
  5. Development (Coding)
  6. Testing & Quality Assurance
  7. Implementation / Deployment
  8. Maintenance & Review

SDLC Models

Topic 5
Model

Waterfall Model

Sequential, phase-by-phase approach. Each phase must be completed before the next begins. Heavy documentation. Good for well-defined requirements.

⚡ Advantage: Simple, structured. Disadvantage: Inflexible to changes.
Model

Prototyping Model

Iterative development with continuous user feedback. A working prototype is built early and refined through iterations.

⚡ Good when requirements are unclear.
Model

Spiral Model

Combines design and prototyping with risk management. Each spiral cycle includes planning, risk analysis, engineering, and evaluation.

⚡ Best for high-risk, large projects.
Model

Agile Model

Flexible and adaptive; emphasizes collaboration and continuous delivery. Works in short sprints. Examples: Scrum, XP (Extreme Programming).

⚡ "Working software over comprehensive documentation."

Role of the System Analyst

Topic 6
Role

System Analyst

A professional who acts as a bridge between business needs and technical solutions.

  • Understanding user requirements and system needs
  • Modeling business processes and data flows
  • Designing and evaluating system alternatives
  • Communicating with management and technical teams
  • Supporting testing, documentation, and implementation
Skills Required

Analyst Skills

  • Technical knowledge (systems, databases)
  • Communication & interpersonal skills
  • Problem-solving and analytical thinking
  • Business domain knowledge
  • Knowledge of UML and modeling tools

Development Approaches & Trends

Topic 7
Approach

Traditional / Structured

Based on SDLC with defined stages. Heavy documentation, sequential. Examples: Waterfall, SADT (Structured Analysis and Design Technique).

Approach

Object-Oriented (OO)

Models systems using objects combining data and behavior. Uses UML (use case, class, sequence diagrams).

Approach

Agile Approach

Emphasizes flexibility, collaboration, rapid iteration. Examples: Scrum, Extreme Programming (XP). Prioritizes working software over documentation.

Current Trends

Modern Trends in SAD

  • Cloud-based system development
  • DevOps & CI/CD integration
  • AI-assisted development tools
  • Microservices architecture
  • Low-code/No-code platforms
  • Cybersecurity-first design
