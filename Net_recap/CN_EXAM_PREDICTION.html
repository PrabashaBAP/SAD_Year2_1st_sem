Part B — Subnetting Worked Answer (Q3c)

Q3c.I: Total usable hosts in 192.168.10.0/24 before subnetting

/24 = 8 host bits. Total IPs = 2^8 = 256. Usable hosts = 256 - 2 = 254 (subtract network address and broadcast address)

Q3c.II: New subnet mask for 4 equal subnets
Need 4 subnets: borrow 2 bits (2^2 = 4 subnets) New prefix: /24 + 2 = /26 Binary mask: 11111111.11111111.11111111.11000000 New subnet mask: 255.255.255.192 (/26) Each subnet: 64 IPs, 62 usable hosts
Q3c.III: First subnet network address and broadcast address
First Subnet: Network Address: 192.168.10.0 First Usable: 192.168.10.1 Last Usable: 192.168.10.62 Broadcast: 192.168.10.63 Second Subnet: 192.168.10.64 to 192.168.10.127 Third Subnet: 192.168.10.128 to 192.168.10.191 Fourth Subnet: 192.168.10.192 to 192.168.10.255
Q3d: Two IPv4 limitations requiring transition to IPv6
  • Address exhaustion: IPv4 uses 32-bit = only 4.29 billion addresses. With IoT explosion, these were exhausted. IANA distributed last blocks in 2011.
  • NAT complexity: To work around exhaustion, NAT (Network Address Translation) was introduced but it breaks end-to-end connectivity and creates problems for peer-to-peer applications.
  • IPv6 solution: 128-bit = 3.4x10^38 addresses, built-in IPsec, auto-configuration, no NAT needed.

RMA, Metrics & Performance
Explain the RMA requirements (Reliability, Maintainability, Availability). Define MTBF and MTTR and show how to calculate network availability with a worked example.
20 MarksVery Likely
▼
Model Answer
  • Reliability (R): Ability of a network to perform required functions consistently. Measured by MTBF. High MTBF = reliable network.
  • Maintainability (M): Ease and speed of restoring a network after failure. Measured by MTTR. Low MTTR = fast recovery = good maintainability.
  • Availability (A): Proportion of time network is operational. Calculated from MTBF and MTTR.
  • MTBF (Mean Time Between Failure): Average time a component operates without failure. Example: server fails every 1000 hours → MTBF = 1000h
  • MTTR (Mean Time to Repair): Average time to restore failed component. Example: restoration takes 5 hours on average → MTTR = 5h
Availability = MTBF / (MTBF + MTTR) Example: MTBF = 1000h, MTTR = 5h Availability = 1000 / (1000 + 5) = 1000/1005 = 99.5% "Five Nines" = 99.999% = only 5.26 minutes downtime per year!

Cryptography
Compare DES, 3DES, and AES encryption. Why did AES replace 3DES? Explain the digital signature process and describe the three security services it provides. (20 marks)
20 MarksSure to Appear
▼
Model Answer
AlgorithmKey SizeBlock SizeTypeStatus
DES56 bits64 bitsSymmetric (Feistel)Deprecated 2005 — brute-forced in 22hrs
3DES (TDEA)168 bits (3x56)64 bitsSymmetric (3x DES)Deprecated — 3x slower; small block
AES128/192/256 bits128 bitsSubstitution-permutationCurrent standard — brute force impractical

Why AES replaced 3DES: 3DES is 3x slower than DES. Both use 64-bit block size (outdated). NIST called for AES in 1997 requiring 128-bit blocks, 128/192/256-bit keys, security beyond 3DES, and improved efficiency. AES uses substitution-permutation network (not Feistel) for superior mixing.

Digital Signature Process:

  • Sender creates a HASH of the document (using MD5/SHA-256)
  • Sender encrypts the hash with their own PRIVATE KEY → this IS the digital signature
  • Document + signature sent to recipient
  • Recipient uses sender's PUBLIC KEY to decrypt signature → recovers hash
  • Recipient independently hashes the received document and compares hashes
  • If hashes match → document is authentic and unaltered

Three security services provided:

  • Authentication: Proves message came from the claimed sender (only they have the private key)
  • Integrity: Proves message was not modified in transit (hash mismatch = tampering)
  • Non-repudiation: Sender CANNOT deny sending the message

Model Answer — VLSM Curveball (Most Likely Real Exam Surprise!)

VLSM Rule: Sort departments by size LARGEST first, then allocate smallest possible subnet for each, in sequence.

Sort: Dept A (100) > Dept B (40) > Dept C (20) > Dept D (10) Dept A (need 100 hosts): Need >= 102 IPs (100+2) -> 2^7=128 >= 102 -> /25 (126 usable) Subnet: 172.16.0.0/25 Mask: 255.255.255.128 Network: 172.16.0.0 Range: 172.16.0.1 to 172.16.0.126 Broadcast: 172.16.0.127 Dept B (need 40 hosts): Need >= 42 IPs -> 2^6=64 >= 42 -> /26 (62 usable) Subnet: 172.16.0.128/26 Mask: 255.255.255.192 Network: 172.16.0.128 Range: 172.16.0.129 to 172.16.0.190 Broadcast: 172.16.0.191 Dept C (need 20 hosts): Need >= 22 IPs -> 2^5=32 >= 22 -> /27 (30 usable) Subnet: 172.16.0.192/27 Mask: 255.255.255.224 Network: 172.16.0.192 Range: 172.16.0.193 to 172.16.0.222 Broadcast: 172.16.0.223 Dept D (need 10 hosts): Need >= 12 IPs -> 2^4=16 >= 12 -> /28 (14 usable) Subnet: 172.16.0.224/28 Mask: 255.255.255.240 Network: 172.16.0.224 Range: 172.16.0.225 to 172.16.0.238 Broadcast: 172.16.0.239
VLSM vs FLSM: FLSM = all subnets SAME size (wastes IPs). VLSM = each subnet sized to ACTUAL need (efficient). VLSM is what real networks use. Tutorial 05 covered this — mock did NOT test it = likely real exam curveball!

Master Formula Reference

KEY SUBNETTING FORMULAS: ------------------------------------------------- Host bits = 32 - prefix length Example: /26 means 32-26 = 6 host bits Total IPs per subnet = 2^(host bits) Example: /26 has 2^6 = 64 total IPs Usable hosts = 2^(host bits) - 2 Example: /26 has 64 - 2 = 62 usable hosts Number of subnets (FLSM) = 2^(borrowed bits) Example: borrow 2 bits from /24 -> 4 subnets QUICK REFERENCE TABLE: /25 -> 7 host bits -> 128 IPs -> 126 usable (mask: .128) /26 -> 6 host bits -> 64 IPs -> 62 usable (mask: .192) /27 -> 5 host bits -> 32 IPs -> 30 usable (mask: .224) /28 -> 4 host bits -> 16 IPs -> 14 usable (mask: .240) /29 -> 3 host bits -> 8 IPs -> 6 usable (mask: .248) /30 -> 2 host bits -> 4 IPs -> 2 usable (point-to-point)
Worked Example 1 — FLSM (Tutorial 04 / Mock Q3c Pattern)

Given: 192.168.20.0/24 — Divide into 4 equal subnets

Step 1: Original = /24 (8 host bits, 256 total IPs, 254 usable) Step 2: Need 4 subnets -> borrow 2 bits (2^2 = 4 subnets) ✓ Step 3: New prefix = /24 + 2 = /26 Step 4: Mask = 11111111.11111111.11111111.11000000 = 255.255.255.192 Step 5: Each subnet has 2^6 - 2 = 62 usable hosts Subnet 1: Network=192.168.20.0 Range=.1 to .62 Broadcast=.63 Subnet 2: Network=192.168.20.64 Range=.65 to .126 Broadcast=.127 Subnet 3: Network=192.168.20.128 Range=.129 to .190 Broadcast=.191 Subnet 4: Network=192.168.20.192 Range=.193 to .254 Broadcast=.255

Device OSI Layers

  • Hub = Layer 1 (Physical)
  • Repeater = Layer 1 (Physical)
  • Bridge = Layer 2 (Data Link)
  • Switch = Layer 2 (Data Link)
  • Router = Layer 3 (Network)
  • Gateway = Layer 3+ (Network+)
  • CSU/DSU = between Router & WAN

Hub vs Switch

  • Hub: broadcasts to ALL ports
  • Switch: sends to SPECIFIC port
  • Hub: one collision domain total
  • Switch: each port = collision domain
  • Hub: half duplex only
  • Switch: full duplex capable
  • Hub: Layer 1 | Switch: Layer 2

Availability Formula

  • MTBF = Mean Time Between Failure
  • MTTR = Mean Time to Repair
  • MTBF measures Reliability (R)
  • MTTR measures Maintainability (M)
  • A = MTBF / (MTBF + MTTR)
  • 5 Nines = 99.999% uptime
  • 5 Nines = 5.26 min/year downtime

CIA Triad + Attacks

  • Interception (passive) = Confidentiality
  • Modification (active) = Integrity
  • Interruption DoS (active) = Availability
  • Fabrication (active) = Integrity
  • Passive = observe only, hard to detect
  • Active = deliberate action on data

IPv4 Classes

  • Class A: 1-126 | first bit=0 | /8
  • Class B: 128-191 | bits=10 | /16
  • Class C: 192-223 | bits=110 | /24
  • Private A: 10.0.0.0/8
  • Private B: 172.16.0.0/12
  • Private C: 192.168.0.0/16
  • Loopback: 127.0.0.1

Subnetting Quick Table

  • /25 = 126 usable (mask: .128)
  • /26 = 62 usable (mask: .192)
  • /27 = 30 usable (mask: .224)
  • /28 = 14 usable (mask: .240)
  • /29 = 6 usable (mask: .248)
  • /30 = 2 usable (point-to-point)
  • Formula: Usable = 2^n - 2

Cryptography Quick Ref

  • DES: 56-bit key, 64-bit block, DEAD
  • 3DES: 168-bit, 64-bit block, slow
  • AES: 128/192/256-bit, 128-bit block
  • Symmetric: 1 key (same enc/dec)
  • Asymmetric: public + private pair
  • RSA: most common asymmetric

Digital Signatures

  • SIGN: sender's PRIVATE key
  • VERIFY: sender's PUBLIC key
  • ENCRYPT: recipient's PUBLIC key
  • DECRYPT: recipient's PRIVATE key
  • Provides: Auth + Integrity + Non-repudiation
  • Hash: MD5 (128-bit), SHA-256 (256-bit)

Firewall Types

  • Packet Filter: Layer 3, IP headers
  • Circuit-level: TCP handshake check
  • Application Proxy: Layer 7, content
  • Stateful: connection state table
  • NGFW: DPI + IDS/IPS + ML + AV
  • WAF: web apps (SQL/XSS protection)
  • DMZ = public server buffer zone

IDS vs IPS

  • IDS = PASSIVE (detect + report only)
  • IPS = ACTIVE (detect + block)
  • NIDS: network-wide, Snort
  • HIDS: per-host, OSSEC, Tripwire
  • IPS placed IN-LINE in network path
  • Detection: Signature, Anomaly, Policy

Topology Summary

  • Star: most common LAN, central = SPOF
  • Bus: simple, cable break = all down
  • Ring: token passing, orderly access
  • Tree: best for WAN/corporate
  • Mesh: max redundancy, most expensive
  • Physical=layout | Logical=data flow

Performance Metrics

  • Bandwidth = max capacity (bps)
  • Throughput = actual data delivered
  • Latency = packet travel time
  • Jitter = variation in delay (VoIP!)
  • Packet Loss = % not delivered
  • Order: Throughput <= Bandwidth

FCAPS Management

  • F = Fault (detect, fix failures)
  • C = Configuration (track settings)
  • A = Accounting (usage/billing)
  • P = Performance (QoS monitoring)
  • S = Security (access control)
  • Mock Q1 = Security Management

Transmission Media

  • Guided: Twisted pair, Coaxial, Fiber
  • Unguided: Wireless, Satellite, RF
  • Fiber: highest bandwidth, immune EMI
  • Twisted pair: twisting reduces interference
  • CAT5e: 1Gbps | CAT6: 10Gbps
  • Coaxial: TV cable, older networks
